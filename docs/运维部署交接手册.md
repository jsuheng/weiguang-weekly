# 周报系统：公司内网部署交接手册

## 1. 交付内容

系统是有后端的全栈应用，不是静态网页。部署包应至少包含：

- 应用源码、`Dockerfile`、`docker-compose.yaml`、`.gitlab-ci.yml`；
- PostgreSQL 迁移、服务器文件目录接口和账号初始化脚本；
- `.env`、备份恢复脚本、预检脚本；
- 本手册、`docs/服务器文件存储说明.md` 和压缩包 SHA-256 校验文件。

Leader 与实习生共用一个内网域名。用户不能通过 URL 参数选择职位，权限仅取自数据库成员关系。

## 2. 服务器要求

- Linux x86_64；
- Docker Engine 24+、Docker Compose v2；
- 至少 4 核 CPU、8 GB 内存、100 GB 可用磁盘；
- 持久目录 `/data/weiguang/postgres`、`/data/weiguang/files`、`/data/weiguang/backups`；
- 服务器能够拉取公司 Harbor、PostgreSQL 与 Alpine 镜像；
- Caddy 或公司内网反向代理能够访问服务器 7019 端口。

PostgreSQL 不映射宿主机端口，仅应用端口 7019 可被反向代理访问。上传文件由应用直接写入宿主机 `/data/weiguang/files`，不经过其他文件服务。防火墙应只允许公司 Caddy 主机和必要运维网段访问 7019。

## 3. 配置

复制 `.env.example` 为 `.env`，至少更换：

- `APP_BASE_URL`：正式内网地址；
- `PASSWORD_PEPPER`：至少 32 位随机值，丢失后已有密码无法验证；
- `CRON_SECRET`：至少 32 位随机值；
- `POSTGRES_PASSWORD` 与 `DATABASE_URL` 中的密码；
- `FILE_STORAGE_DIR=/data/files`：应用容器内文件目录；
- `FILE_STORAGE_HOST_PATH=/data/weiguang/files`：宿主机持久目录；
- `APP_IMAGE`：当前 GitLab CI 构建的 Harbor 镜像。

HTTPS 环境使用 `COOKIE_SECURE=auto`；临时 HTTP 内网可设置为 `false`，但密码和会话链路不受 TLS 保护。

不要在已有数据库上修改 `PASSWORD_PEPPER`。生产 `.env` 权限应为 `600`。

## 4. 首次部署

```bash
mkdir -p /data/gitlabci/weiguang-weekly
mkdir -p /data/weiguang/postgres /data/weiguang/backups
install -d -m 0750 -o 1000 -g 1000 /data/weiguang/files
cd /data/gitlabci/weiguang-weekly

cp .env.example .env
chmod 600 .env
# 填写配置后：
bash scripts/preflight.sh
docker compose --env-file .env up -d
curl -fsS http://127.0.0.1:7019/api/health
bash scripts/bootstrap-leader.sh leader "Leader姓名" "内容增长组"
```

初始化脚本只创建一个 Leader。临时密码不会写入源码，首次登录必须修改。之后由 Leader 在“成员管理”中创建实习生或额外 Leader。

## 5. 内网域名与 Caddy

建议由内网 DNS 将一个域名解析到 Caddy，例如 `weekly.internal.company`。Caddy 反向代理到 `10.63.14.182:7019`：

```caddy
weekly.internal.company {
  reverse_proxy 10.63.14.182:7019
}
```

优先使用公司 CA 或受信任证书提供 HTTPS。Leader 和实习生不需要不同域名。

## 6. GitLab CI

- `test` 分支：校验、构建、自动部署测试环境；
- `main` 分支：校验、构建，生产部署需要手动确认；
- `rollback_prod`：恢复上一应用镜像。

CI 变量：

- `HARBOR_USERNAME`、`HARBOR_PASSWORD`；
- `SSH_PRIVATE_KEY`；
- `SSH_KNOWN_HOSTS`：测试和生产服务器真实 SSH 主机公钥；
- 可选 `SSH_USER`，默认 root。

服务器上的 `.env` 不由 CI 覆盖。每次部署前会执行数据库和文件目录备份；健康检查使用 `/api/health`。

应用回滚不会反向执行数据库迁移。迁移必须保持向后兼容；破坏性迁移需要单独变更窗口、备份和恢复演练。

## 7. 备份与恢复

建议由服务器 Cron 每天执行：

```cron
15 2 * * * cd /data/gitlabci/weiguang-weekly && set -a && . ./.env && set +a && sh scripts/backup.sh >> /var/log/weiguang-backup.log 2>&1
```

备份默认写入 `/data/weiguang/backups` 并保留 14 天。至少每季度执行一次恢复演练：

```bash
set -a
. ./.env
set +a
sh scripts/restore.sh /data/weiguang/backups/YYYYMMDD_HHMMSS
```

恢复会覆盖当前数据库与文件，脚本要求输入 `RESTORE` 二次确认。

## 8. 账号运维

- 成员忘记密码：Leader 在成员管理中重置，临时密码只显示一次；
- Leader 修改自己的密码：个人菜单或小组设置；
- 首个/最后一个 Leader 忘记密码：运维重新执行 `scripts/bootstrap-leader.sh`，同用户名会重置密码并注销旧会话；
- 连续 5 次错误密码：账号锁定 15 分钟；
- 停用成员：立即注销会话、保留历史周报和导入记录、未完成任务标记待转交；
- 系统不保存成员手机号，也不会向外部渠道发送通知。

## 9. 验收

1. `/api/health` 返回 `status: ok`，数据库和服务器文件目录均为 true；
2. Leader 临时密码登录后必须修改；
3. Leader 创建实习生账号，实习生改密后进入实习生界面；
4. 实习生不能进入成员管理、审核或 Leader 点评功能；
5. CSV/XLSX 上传后，原文件进入 `/data/weiguang/files`，批次进入 PostgreSQL；
6. 重启全部容器后任务、周报和导入数据仍存在；
7. 任务临期、逾期和周报截止能生成站内通知；
8. 执行一次备份并在测试环境完成恢复。
