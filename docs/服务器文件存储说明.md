# 服务器文件存储说明

## 存储结构

网站不依赖 MinIO 或其他对象存储服务。上传的 Excel、CSV 和附件由应用直接写入：

```text
/data/weiguang/files/
└── groups/
    └── <group-id>/
        └── imports/
            └── <batch-id>/
                ├── <原始文件名>
                └── <原始文件名>.metadata.json
```

PostgreSQL 的 `file_objects` 表保存文件名称、相对键、大小和 SHA-256；文件二进制保存在上述服务器目录。

## Docker 映射

`docker-compose.yaml` 将宿主机目录映射到应用容器：

```yaml
volumes:
  - ${FILE_STORAGE_HOST_PATH:-/data/weiguang/files}:/data/files
```

生产环境变量：

```dotenv
FILE_STORAGE_DIR=/data/files
FILE_STORAGE_HOST_PATH=/data/weiguang/files
```

## 首次部署权限

应用容器使用非 root 的 Node 用户（UID/GID 1000）运行，首次部署必须执行：

```bash
install -d -m 0750 -o 1000 -g 1000 /data/weiguang/files
```

若 `/api/health` 中 `fileStorage` 为 `false`，优先检查目录挂载、剩余磁盘和 UID/GID 权限。

## 健康检查

`GET /api/health` 会：

1. 检查 PostgreSQL；
2. 在文件目录创建一个临时探针文件；
3. 删除探针文件；
4. 两项均成功才返回 HTTP 200。

## 备份与恢复

`scripts/backup.sh` 生成：

- `postgres.dump`：PostgreSQL 备份；
- `files.tar.gz`：服务器文件目录备份；
- `docker-compose.yaml` 和 `env.snapshot`。

`scripts/restore.sh` 会停止应用、恢复数据库和文件目录，并将恢复前文件目录改名保留，避免直接删除。
